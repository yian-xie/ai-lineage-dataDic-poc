KEY

A few terms in plain language

HVR

The configured replication service that captures, converts, and delivers source files.

Airflow

The job scheduler that coordinates file copies and the Snowflake load.

dbt and RAW

dbt is the transformation layer. RAW is the first Snowflake landing table before account models reshape the data.

The account-data journey

The account slice starts with the `KWDW_ACC` BASIC job. It reads account and transaction records and writes the pipe-delimited `DWACC` extract.

STAGE 01Ultracs records

ACCOUNT and TRAN are read by the legacy job.

STAGE 02KWDW_ACC → DWACC

The job transforms selected fields and writes the extract.

STAGE 03HVR delivery

Two configured branches carry the extract toward Snowflake.

STAGE 04Account models

Airflow loads RAW; dbt builds internal and public account views.

Direct HVR route

HVR to its configured Snowflake landing relation

DWACC → ult_sf_acc → LOADACCOUNTS_INGEST

The HVR configuration declares row-level `payload` and `integration_timestamp` columns. This graph does not connect that landing relation to the account-v1 RAW table.

S3 and account-ingestion route

HVR files into the account product

DWACC → Parquet/HVR S3 → Datalake S3 → RAW.ACCOUNTS_V1__ACCOUNTS → dbt

The Airflow DAG declares the copy and load steps. dbt source/model dependencies lead to account-detail, EOD-balance, and public account relations.

Important boundary: the direct HVR route and the S3/Airflow route remain separate. The extract-to-capture filename match is inferred; repository configuration does not prove the direct landing table feeds account-v1 RAW.

How to read confidence and descriptions

The score accompanies the original evidence label. It is a fixed heuristic for communicating evidence strength—not a statistical probability, runtime success rate, or guarantee.

Graph labelDisplay scoreMeaning
runtime_verified100%Reserved for an exact path observed in a successful production-equivalent run and corroborated against live object metadata. No current POC edge has this evidence.
explicit / confirmed95%Direct repository evidence supports the relationship. Static files may still be stale or differ from production, so the score is not 100%.
confirmed_calculated90%The calculation is evidenced, but the value is derived rather than a direct copy.
declared_source85%A source is declared in repository metadata; no live catalog/runtime check was performed.
inferred60%Indirect evidence supports a candidate, such as a filename-pattern capture match or composite key.
unconfirmed50%A candidate exists but needs owner or source validation.
unknown / unresolved / missingNot ratedNo score is assigned without a recognized evidence category; missing confidence is not zero.

The lowest numeric level currently defined is 50% (unconfirmed). These percentages are heuristic evidence-strength labels, not probabilities. The skills index includes the confidence scoring guidance.

Description tags also matter:

Repository sourced

Description text comes from checked-in BASIC/HVR/dbt/source metadata or another cited repository artifact.

Repository evidence

A relationship summary uses checked-in edge evidence or mapping notes.

Generated

A literal role/direction summary added for navigation when no repository description exists. It is not business evidence or an authoritative dictionary definition.

Enterprise limitation: descriptions and types on the account column mappings come from dbt metadata. The Enterprise continuation is table-level; generated summaries there do not establish column mappings or datatypes.
07

Open gaps to resolve

These are documented limitations in the current evidence, not claims that production data is broken.

Gap 01 · Traversal

Source reads point toward the source node

The stored relationship is `PROGRAM → READS_FROM → MV_FILE`. A user starting at ACCOUNT must reverse that relationship to read the path in source-to-consumer order.

Gap 02 · Route join

The direct HVR landing has no proven bridge to account RAW

`ult_sf_acc` ends at `LOADACCOUNTS_INGEST`; the account-v1 RAW route begins from the S3/Airflow load. No checked-in evidence joins those branches.

Gap 03 · dbt relations

Model dependencies are clearer than physical-table continuity

`DEPENDS_ON` connects dbt models, and `MATERIALIZES_AS` connects each model to its physical relation. A relation-to-model consumption edge is not present between model layers.

Inferred route limitation: the HVR parser now retains `Capture.Pattern`, and the combined table graph includes 186 `CARRIED_BY` matches from representative BASIC output filenames. These links remain inferred because a filename-pattern match does not confirm runtime delivery.
